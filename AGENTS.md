# AGENTS.md

Правила и договорённости для этого репозитория. Читай перед правкой `.bat`-файлов.

## Что это

Набор коротких обёрток над `git` для Windows (`cmd.exe`), чтобы не набирать
длинные команды: `gc` (checkout), `gcb` (checkout -b), `gp` (pull), плюс
установщик, который прописывает каталог в пользовательский `PATH`.

Никакой сборки, зависимостей и автотестов нет: это обычные пакетные файлы,
которые должны работать «двойным щелчком» и из `cmd.exe`.

## Структура

| Файл | Назначение |
|------|------------|
| `gc.bat` | обёртка над `git checkout` (переключение веток, `-b`/`-B`, откат путей) |
| `gcb.bat` | обёртка над `git checkout -b` (создать/пересоздать/orphan-ветку) |
| `gp.bat` | обёртка над `git pull` (угадывает remote/ветку при отсутствии upstream) |
| `install.bat` | установка: переменная окружения `GLV_GIT_ALIASES` + элемент `PATH` |
| `AGENTS.md` | этот файл |

## Общие договорённости по коду

- Только `cmd.exe`: **никакого PowerShell**, WMI, сторонних утилит. Разрешены
  `git`, `reg`, `setx`, `where` — они есть в Windows по умолчанию.
- Формат файлов: **UTF-8 без BOM, переводы строк CRLF** (в репозитории
  `core.autocrlf=true`). Не пересохраняй файлы в LF/UTF-16.
- Первая строка — `@echo off`, затем `setlocal EnableExtensions`.
  `EnableDelayedExpansion` включай **только** локально и только когда нужно
  (см. `install.bat`): с ним ломаются пути/значения, содержащие `!`.
- Вверху файла — блок `rem ===...===` с описанием, поддерживаемым синтаксисом
  и примерами. Он дублирует справку, но читается прямо в проводнике.
- Ветка `:help` + обработка `-h`, `/?`, `--help` — обязательны для каждой
  обёртки. Текст справки — по-русски, с примерами вызовов.
- Комментарии и сообщения пользователю — **по-русски**, сообщения об ошибках
  короткие, с подсказкой «что делать дальше».

## Разбор аргументов

Единый паттерн во всех обёртках — метки + `shift`, без `for`-магии:

```bat
:parse
if "%~1"=="" goto check_git
set "ARG=%~1"
...
shift
goto parse
```

- Любая опция вида `--opt` или `--opt=value` **пробрасывается в git как есть**
  (складывается в `OPTS`). Не пытайся валидировать неизвестные опции.
- Опции, которым нужно отдельное значение (`-b`, `-B`, `--orphan`,
  `--conflict`, `--pathspec-from-file`, `--from` в `gcb`), обрабатываются
  отдельной веткой `:takes_value` с проверкой наличия второго аргумента.
- Всё после `--` — пути, передаются в хвост команды без интерпретации.
- Собственные «улучшения» скрипта делай через отдельные флаги (например
  `--from`), а не меняя смысл опций git.

## Выполнение и вывод

- Перед запуском печатай саму команду: `echo ^> %CMD%` — пользователь должен
  видеть, что реально выполнилось. `^>` обязателен, иначе `>` создаст файл.
- Ошибки — в stderr через `>&2`, с префиксом имени команды:
  `gc:`, `gcb:`, `gp:`, `install:`.
- Код возврата git пробрасывается наружу (`exit /b %RC%`), не подменяй его на 0.
- Свои коды возврата:

  | Код | Значение |
  |-----|----------|
  | `0` | успех |
  | `1` | логическая ошибка (ветка уже существует, detached HEAD, сбой записи) |
  | `2` | неверные аргументы (нет имени ветки, лишние позиционные, опция без значения) |
  | `127` | `git` не найден в `PATH` |
  | `128` | текущий каталог не git-репозиторий |
  | `129` | не найдена начальная точка (ветка/тег/коммит) |

## Особенности файлов

- `install.bat` пишет только в `HKCU\Environment`, права администратора не нужны
  и требовать их нельзя. В `PATH` кладётся **ссылка** `%VAR%`, а не буквальный
  путь, чтобы папку можно было переносить.
- `setx` используется ради широковещательного сообщения `WM_SETTINGCHANGE`
  (Проводник перечитывает окружение), а не для записи значения: он обрезает
  значения длиннее 1024 символов, поэтому после него значение перепроверяется
  и при необходимости пишется через `reg add`.
- Кодировка консоли: `install.bat` включает `chcp 65001`, обёртки — нет,
  они печатают в текущей кодовой странице. Правя русские сообщения, проверь,
  что они остаются читаемыми и в `cp866`, и в `cp65001`.
- Пути с `!` и UNC-пути обрабатываются отдельно (предупреждение/отказ) —
  не удаляй эти проверки, они появились из-за реальных проблем.

## Как добавлять новую обёртку

1. Имя — короткое, с префиксом `g`, две-три буквы (`gs.bat` для `status`).
2. Скопируй каркас из `gp.bat` (самый простой) и сохрани те же соглашения:
   шапка, `:parse`, проверки `git --version` / `git rev-parse --git-dir`,
   `:run`, `echo ^> %CMD%`, `:help`.
3. Обнови список файлов в шапке `install.bat` и таблицу в этом `AGENTS.md`.
4. Ничего не регистрируй в `PATH` пофайлово: установщик добавляет весь каталог.

## Проверка перед коммитом

Автотестов нет, поэтому проверяй вручную в отдельном временном репозитории:

```bat
cmd /c gc -h
cmd /c gcb -h
cmd /c gp -h

rem позитивные сценарии
cmd /c gcb test-branch
cmd /c gc main
cmd /c gc -B test-branch main
cmd /c gp

rem негативные: должны дать код 2/127/128 и внятное сообщение
cmd /c gcb
cmd /c gcb -B
cmd /c gc --bad-option
cd %TEMP% && cmd /c gc main
```

Минимальный чек-лист:

- [ ] `-h`, `/?`, `--help` печатают справку и возвращают `0`;
- [ ] опции git (`--quiet`, `--detach`, `--rebase`, `--opt=value`) доходят до git;
- [ ] `echo ^> %CMD%` показывает ровно ту команду, которая выполнилась;
- [ ] сообщения об ошибках идут в stderr и содержат подсказку;
- [ ] код возврата совпадает с кодом git при ошибке;
- [ ] файл остался в UTF-8 без BOM с CRLF.

## Коммиты

Стиль, сложившийся в репозитории (придерживайся его):

```
FEAT: Install and gcb
FEAT(GC): Adding git checkout script
Start: adding git pull wrapper\alias script
```

То есть `<ТИП>[(ОБЛАСТЬ)]: <краткое описание>`, где тип — `FEAT`, `FIX`,
`DOCS`, `Start`, область — имя скрипта (`GC`, `GCB`, `GP`, `INSTALL`).
Описание можно по-английски или по-русски, но в одном коммите — на одном языке.
Коммит должен содержать один логический шаг; обновление `AGENTS.md` при смене
договорённостей — часть того же коммита.
